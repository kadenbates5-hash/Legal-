                                    Two-factor authentication

                                    A password is the credential most likely to be phished or reused, and this system holds case files, trust balances and the audit log behind it. A second factor is a six-digit code from an app on your phone — Google Authenticator, 1Password, Authy, anything that scans an otpauth:// link.

                                    1. Add this account to your authenticator app — either open the link on the phone itself, or type the key in by hand:

                                    otpauth link

                                    2. Then type the code it shows. Nothing changes until this succeeds, so a mistyped key can't lock you out:

                                    unused recovery codes remain.

                                    Recovery codes — save these now

                                    These are shown once and stored hashed, so this screen is the only place they exist. Each works exactly once, in place of a code from your app. Print them or put them in a password manager: without them, a lost phone means asking an attorney to reset your second factor, which is recorded in the audit log.

                                                                    Attorney-only, append-only and privilege-sensitive: every access grant and denial, escalation, work-product transition, matter-record edit, document upload or deletion, account change, and money movement — who did it, when, and for record edits, exactly what changed. There is no code path that edits or removes an entry, and the hash chain below makes that checkable rather than something you have to take on trust.
                                                                    
      
                                                                    
        
                                                                    
          
          
          
          
          
          
          
        
                                                                    
      
                                                                    
      
                                                                    
        
                                                                    
          
                                                                    Record integrity
                                                                    
          
          
        
                                                                    
        
                                                                    Each entry is hashed together with the one before it, so altering or deleting one breaks the chain. On its own that catches an edit made in place — but not a log rebuilt from scratch, since a rebuilt chain is still a valid chain. Anchoring closes that: it publishes the current head hash somewhere outside this database, so the record can later be checked against a copy whoever administers the database could not have changed.
